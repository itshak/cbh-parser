# AGENTS.md — cbvault AI Agent Instructions

> Canonical "README for AI agents". Read this before making any change.

## Mission

`cbvault` (formerly `cbh-parser`) reads ChessBase databases (classic `.cbh` family, 2CBH `.2cbh` family, `.cbv`/`.cbz` archives) as a fast, MIT-licensed Rust library and CLI. It is the BYOD foundation for BlindBase: users bring their own databases; nothing is redistributed. **Read-only, always** — this project never writes ChessBase data.

## Tech stack

- Rust (stable toolchain, edition 2024); `cargo fmt`, `cargo clippy`, `cargo test`.
- `gigachess` — the only chess core (bitboards, 16-bit `moves2`, FEN/SAN/UCI, incremental Polyglot Zobrist).
- Criterion for benchmarks; `cargo-fuzz` where parsing is involved.

## OpenSpec workflow

- Specs live in `openspec/specs/`; active changes in `openspec/changes/`.
- Before coding: read the active change and the capability spec it touches.
- Prefix every git commit with the change ID: `[bootstrap-cbh-parser] Add cbh index reader`.
- Before declaring done: `openspec validate <change> --strict`, `cargo fmt --check`, `cargo clippy`, `cargo test`.

## Licensing & provenance (non-negotiable)

1. **MIT only in the tree.** Ported `cbformat` code keeps its upstream MIT headers and is listed in `THIRD_PARTY_NOTICES.md`.
2. **Never copy** code, text or tables from unlicensed (`morphy`) or GPL (`scidb`, `libcbh`, `uncbv`, `Source2Metal`) sources. They are *oracles* (separate processes, tests only) and *facts* references — nothing more.
3. Every module records its provenance (ported / clean-room / original) in `docs/provenance.md`.
4. No outreach to third-party authors on behalf of this project; attribution is documented, contact is the owner's call.

## Chess-core rules

- `gigachess` is the single source of chess semantics: move generation, legality, FEN/SAN/UCI, Chess960, Polyglot Zobrist.
- Internal move currency is 16-bit `moves2` (`from | to<<6 | promo<<12`); castling uses king→rook squares (`e1h1`, `e1a1`, including Chess960).
- Never add a second chess implementation (no `chesscore`, no `shakmaty`, no ad-hoc move logic). If something is missing, add it to `gigachess`.

## Performance rules

- Zero-allocation hot paths: reuse buffers, stream games, no per-game heap churn, no intermediate strings.
- FEN/SAN/UCI strings only at output boundaries.
- Benchmarks before and after every performance change; budgets live in the change's design.
- Malformed input must never panic: typed errors, keep parsing what is recoverable.

## Testing & fixtures

- Real databases are **local-only** (env var, e.g. `CBH_TEST_DB`); never committed.
- Public CI uses fixtures generated by the in-repo fixture builder; oracle comparisons are opt-in and run as separate processes.
